# SQLite retained goal storage

SQLite runtime publication, completion/failure, discovery, filtering and cell
retirement use retained jobs. Fresh constructors initialize format 14; legacy
11/12/13 constructors return a typed manual-upgrade prerequisite. The read-only
checker validates 11/12/13 and current 14, and the exclusive transactional converter
is available through `sqlite.MigrateGoals` and `jobdb sqlite migrate --db PATH`.
See [manual migration guidance](MIGRATION-IMMUTABLE-GOALS.md). Toy and SQLite advertise enforced
job-goal guarantees; attachment API removal follows completed initial consumer cleanup.

`schema/format-13.sql` plus the additive format-14 resource schema contains the target jobs, cells, schema registry,
wait/subscription and preparation definitions. Event and receipt definitions are
added by `createRetainedGoalSchema`. There is no independent goal/candidate table,
renamed compatibility payload or unconditional active-member uniqueness index.
Inherited live overlaps remain representable. Fresh storage has no schedule
objects or scheduling APIs; dormant historical schedule data survives conversion.
Append generations, delayed availability and lease events retain their meaning.

A unique partial index on `(tenant_id, goal_id)` identifies the origin; another
identifies first closure. Origin ownership and creation time govern an open
recovery gap even if every member is archived or hidden. Sparse closure carries
state, exact closure time, provenance and the real successful producer. Native
success lives on that producer. A historical cross-primary success lives on the
target origin with migrated provenance and references the producer without
changing its primary membership. Protected failure records carry the original
message/time/member snapshot, including historical members of another primary
goal. They have no worker route, lease, task or chapter payload.

`retainedGoalStore` implements the shared transition engine's store, including
transactional protected failure insertion. Its embedded legacy store supplies
only unchanged wait/subscription operations; all goal and membership methods
are overridden. It has no secondary insertion port and reads primary membership from jobs. `CheckAdmission` includes every retained nonterminal member without
filtering hidden rows, deadlines, lease expiry or cancellation requests. It must
run in the same writer transaction as publication, after accepted-request replay.
It is not an admission reservation for preparation.

The runtime writer barrier now uses `UPDATE jobdb_jobs SET job_id=job_id WHERE 0`
before callbacks read scheduler facts. This replaces the former goals-table
reference for both current and target storage. Independent-handle tests verify
that the no-row update actually reserves the WAL writer; contenders cannot
enter their scheduler callback before that reservation is released.

SQL constraints and triggers protect immutable job identity, original ownership,
record kind, saved failure snapshot, first closure and retained origin/closure
rows. Hiding remains an ordinary update. Application code must still provide
existing authority checks; these private methods do not introduce authorization.
The caller owns rollback for insertion, closure and durable waiter settlement.
A failed operation must discard its entire transaction.

`validateRetainedGoalSchema` checks exact target definitions without repairing
schema or advancing a marker. `verifyRetainedGoalFacts` checks published origins,
closed protected records and result witnesses without reading chapters. These
are persistence checks for constructor/converter integrity checks,
not substitutes for its full integrity, receipt/preparation, wait/subscription
and preservation checks. No conversion decision may use stale preflight output.

Historical schema definitions under `schema/legacy-*.sql` are frozen separately
from the target. The supported 11/12 checker compares
against these historical definitions, so adopting a new live schema cannot
silently change what counts as a supported migration input. Historical fixtures under `testdata/` remain frozen. An additional fixture
`goal-upstream-11.sql` was generated by upstream 1dd75e9 and exercises the actual
format-11 append extensions, availability and schedule-free schema.

Real local on-disk tests cover storage transitions, public submission/shared
restart, rollback, independent handles, controlled storage commit orders, reopen,
indexed lookups, conversion and real SQLite-backed HTTP reads. Frozen legacy
fixtures include an actual saved-runtime producer with chapters, an inline input
artifact, accepted selection receipts, configuration and settled dependencies.
Private store fixture executions still have no chapters and cannot by themselves
establish public parity. Reusable public admission conformance now runs through
toy/SQLite and both HTTP adapters. Public controlled commit-order tests, complete
discovery query plans and converted-cell retirement supplement storage evidence.
Toy retained storage and operation-level capability enforcement are implemented;
attachment declarations, mutation routes and CLI commands are removed.
